┌──────────────────────────────────────────────────────────────────────────────┐
│ TERMINAL 1 — FRONTEND SETUP                                                 │
└──────────────────────────────────────────────────────────────────────────────┘

STEP 1 — Go to the frontend folder

    cd V:\Projects\CAPSTONE\frontend


STEP 2 — Check Node.js and npm

    node -v
    npm -v


STEP 3 — Install frontend packages

    npm install

This creates/restores:

    V:\Projects\CAPSTONE\frontend\node_modules\

You normally do NOT need to run npm install every time.

Run it again when:
    • node_modules is missing
    • package.json changed
    • package-lock.json changed
    • frontend dependencies need to be restored


STEP 4 — Start the frontend

    npm run dev

Vite will display a Local URL, for example:

    http://localhost:8080/

The port may be different.
Always open the Local URL shown by Vite.

KEEP TERMINAL 1 OPEN.


┌──────────────────────────────────────────────────────────────────────────────┐
│ TERMINAL 2 — BACKEND SETUP                                                  │
└──────────────────────────────────────────────────────────────────────────────┘

STEP 1 — Go to the backend folder

    cd V:\Projects\CAPSTONE\backend


STEP 2 — Create the Python virtual environment

Only do this if the venv folder does not exist:

    python -m venv venv


STEP 3 — Activate the virtual environment

PowerShell:

    .\venv\Scripts\Activate.ps1

You should see:

    (venv) PS V:\Projects\CAPSTONE\backend>


STEP 4 — Upgrade pip

    python -m pip install --upgrade pip


STEP 5 — Install backend requirements

    python -m pip install -r ..\requirements.txt


STEP 6 — Check installed dependencies

    python -m pip check

If this reports dependency conflicts, fix the requirements first.
Do not randomly install packages.


WINDOWS NOTE
If Windows blocks pip.exe, use:

    python -m pip ...

instead of:

    pip ...

5. GROQ MODEL — WHAT CHANGED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

OLD MODEL
─────────

    llama-3.1-8b-instant


WHY THE OLD MODEL CAUSED THE ERROR
───────────────────────────────────

Your application previously used:

    llama-3.1-8b-instant

Groq deprecated/retired this model for the relevant developer/free usage,
which is why your application can return:

    404
    model_not_found

IMPORTANT
    The old model name may still appear inside:

    venv\Lib\site-packages\groq\

    DO NOT edit those files.

Those are installed Groq SDK files.


NEW MODEL
─────────

Use:

    openai/gpt-oss-20b

This is the replacement to use in your application for the old model.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Open the official Groq API Keys page:

    https://console.groq.com/keys


STEPS
─────

    1. Log in to Groq.
    2. Open API Keys.
    3. Click "Create API Key".
    4. Display Name:
           CAPSTONE
       (or any name you recognize)
    5. Choose the expiration you want.
    6. Create the key.
    7. Copy the key and store it safely.


API KEY FORMAT
──────────────

It normally looks similar to:

    gsk_XXXXXXXXXXXXXXXXXXXXXXXX

The example above is NOT a real key.


SECURITY
────────

NEVER put your real API key in:

    • Run.txt
    • GitHub
    • screenshots
    • chat messages
    • frontend source code
    • public repositories

Keep the key inside the backend .env file.
